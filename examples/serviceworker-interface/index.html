serviceworker-interface page ↔ service worker

⚠ Requires HTTPS or localhost

The page is the GUEST (initiates the handshake) and the service worker is the HOST (waits). A dedicated per-client DDA session is created on the first message from each tab so multiple tabs can each have independent RPC connections to the same service worker.

SW registration demo

The buttons below exercise real Service Worker registration and messaging if you serve this folder from localhost with npm run serve.

Page code (GUEST)

import { createPageInterface }
  from '@actualwave/serviceworker-interface';

await navigator.serviceWorker.register('/sw.js');
await navigator.serviceWorker.ready;

const { root: swApi, stop } = await createPageInterface({
  root: {
    notifyUser(msg) {
      showBanner(msg);
    },
  },
  handshakeTimeout: 5_000,
});

// Call SW methods
const stats = await swApi.getCacheStats();
console.log('Cached:', stats.count);

await swApi.clearExpiredCache();

Service worker code (HOST)

// sw.js
import { createWorkerInterface }
  from '@actualwave/serviceworker-interface';

const server = createWorkerInterface({
  root: makeSwApi(), // per-instance
  handshakeTimeout: 5_000,
  onConnect({ clientId, root: pageApi }) {
    console.log('Client:', clientId);

    // Push back to the page
    pageApi.notifyUser('SW ready!');
  },
});

// sw.js is HOST — one session per tab
self.addEventListener('activate', () => server.stop());

Key design notes

  • Page = GUEST: initiates handshake pings so the SW doesn't need to discover clients.
  • Per-client sessions: each tab gets its own isolated DDA session identified by event.source.id.
  • Bidirectional: the SW can call methods on the page (e.g. push notifications, cache events) just like the page calls SW methods.
  • Auto-cleanup: disconnecting a tab disposes its session; the SW's global listener stays active for new connections.
